# User-installed provider runtimes under `~/.ao/providers`

**Supersedes [ADR 0006](./0006-acp-adapters-as-tauri-resources.md); amends [ADR 0014](./0014-managed-antigravity-acp-runtime.md).**

The bundled `acp-adapter-resources` tree was about 664 MB, roughly 95% of it vendor CLI binaries that npm pulls in as platform optional dependencies and that the launch path never runs (`CLAUDE_CODE_EXECUTABLE` / `CODEX_PATH` already point at the PATH CLIs). Provider runtimes are now **user-initiated installs** under `~/.ao/providers/<launch-target>/`, relying on a **global Node >= 22 and npm** for now (managing Node ourselves is deferred to a production release). The same layout and flow serve desktop and VS Code through `@lib/ui`.

## Decisions

- **Layout.** `providers/<id>/runtime/<version>/` (npm `--prefix`, or the extracted Antigravity binaries), `providers/<id>/current.json`. Antigravity's `home/` (`GEMINI_HOME`) and `browser-helper` move to `providers/antigravity-acp/` (hard move, no migration, pre-alpha).
- **`current.json` selects the active runtime** (version + provider-relative directory; no symlinks) and **catalogs known runtimes** with a discriminated download state (`downloading`, `completed`, `failed`, `pending-delete`). An attempt is cataloged before its directory exists and marked `completed` only after the process exits and the required files validate. Directory existence alone never means a download succeeded. Versions and cleanup targets come from the catalog, never `readDirectory` (unsupported on the VS Code webview FS). Malformed or unreadable state is an error, never an instruction to seed, stop, or delete. It is re-read before every spawn; there is no file watching.
- **Atomic publication** through a host op (`AtomicFile`: temp file beside the target, then rename), constrained to `providers/<id>/current.json` on both hosts.
- **Pinned metadata.** `Check for latest` resolves `npm view <pkg>@latest version`, or the ACP registry `antigravity-acp/agent.json`, once into an exact descriptor (package/version, or version/platform/archive/sha256/command/arguments) that is stored in the catalog. Download and offline launch use the stored descriptor; mutable latest metadata is never fetched again for an already selected version. Registry `arm64`/`x64` map to `aarch64`/`x86_64`; archives must be under `https://dl.google.com/agy-extensions/`; Windows stays excluded.
- **Download is background; Install is explicit.** Check and Download never interrupt the provider or its sessions. The first Download activates automatically; later Downloads only add a completed catalog entry and show **Install**. Install publishes the new active runtime, awaits the local provider stop, bootstraps once, then deletes every superseded and never-activated directory (failed deletions stay cataloged and are retried at startup). Once the new runtime is active the provider is always bootstrapped, so a cleanup failure is reported but never leaves it stopped. **Remove** publishes no active runtime, stops, and deletes all runtime directories; credentials and the enable preference stay, so an enabled provider becomes _Unavailable_. There is no automatic update polling.
- **Disabled vs Unavailable.** Disabled = the user switched it off (no backend, hidden from pickers). Unavailable = enabled but cannot launch (no CLI, no active runtime); it stays visible as a disabled row with a reason. First-run defaults (Claude/Codex on iff their CLI is on PATH; Antigravity/Cursor off) are seeded once, only after Node/npm pass and settings load successfully, and never reapplied.
- **Lifecycle.** One owner per host runtime (`BackendLifecycle`) runs each harness fiber; `stop` interrupts it and awaits finalizers (Tauri kills the tracked process tree; scope close awaits exit). Atoms never own process lifetime, and a per-provider desired-state atom blocks restarts of a stopped backend. Stop reconciles local state: pending requests are cancelled, sessions marked inactive, history and transcripts preserved, nothing reopened automatically. Install, Remove, Disable, Recheck and Sign in warn (Cancel/Continue) when this instance has live sessions.
- **Native boundaries.** Tauri has no symlink to resolve the Antigravity command, so a constrained Rust command (`spawn_antigravity_provider`) reads `current.json` itself and never accepts an executable path or arguments from the webview; VS Code `hostFulfillment` does the equivalent mapping. `npm` is spawned on Tauri only as three operations with pinned scope arguments (`provider-npm-version`, `provider-npm-view`, `provider-npm-install`).

## Accepted limitation: single-instance semantics

Desktop and VS Code share `~/.ao` but do **not** coordinate. Other running instances re-read `current.json` before every spawn, so they pick up a change on their next harness start. An Install or Remove in one instance can delete a directory another running instance is still using, and one instance's startup cleanup can remove another's in-flight download. That race is accepted for pre-alpha; locks, acknowledgments and watchers are tracked in a follow-up issue.

## Considered options

- **Keep bundling, trim optional dependencies:** still ships a Node dependency graph in every package and pins versions to app releases.
- **Sidecar Node / Node in AO home:** deferred; adds platform matrix work before there is a production release.
- **Symlink `current`:** unsupported on the VS Code webview FS and awkward on Windows; `current.json` also carries the catalog.
