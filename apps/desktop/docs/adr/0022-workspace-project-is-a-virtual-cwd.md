# Workspace project is a virtual cwd

A **Project** may be a `.code-workspace` file (a **Workspace project**). It is never used as a Session cwd: a single resolution seam (`resolveProject`) turns a Project path into `{cwd, additionalDirectories, workspaceFile?}` (a directory is the identity case), and every place that treated a Project as a cwd goes through it. ACP ties a session to its cwd on load/resume (ADR 0005), so the cwd is the file's first `file:` folder and the other folders are **Additional directories**.

- **`projects.json` keeps its shape.** A path ending `.code-workspace` is a Workspace project; no migration. Reading the files is separate from resolving: each Workspace file is read at startup and on add into one atom of states (`Resolved` folders, or `Failed`), and the pure seam derives everything from it.
- **Membership.** A Tracked session (or live session) with a Workspace file belongs to that Workspace project when it is a Project, even while errored; otherwise to the directory Project at its cwd. A session that matches no Project has no group (it is not listed, searchable or adoptable either). Session History grouping, listing, Stop tracking and the Project's active sessions all use the one `projectOfRecord` rule, so two Projects that share a first folder never take each other's sessions. We considered also placing a plain session under a Workspace project that lists only its folder; rejected, it would mix sessions the user kept apart.
- **Listing.** `session/list` stays cwd-only, so Import lists the first folder and attributes the rows the user confirms to the Workspace project (stamping the file and the other folders). Rows of a Workspace project are hydrated by its first folder: if the file's first folder changes, sessions recorded under the old one stay dormant.
- **Activation** keeps the stored cwd and re-reads the file for the Additional directories (current folders minus the stored cwd), falling back to the stored list when the file cannot be read.
- **Unresolvable file** (missing, moved, unreadable, outside the home-scoped desktop filesystem, no `file:` folder): the Project stays with a visible error, re-pick and remove actions, one client error, no hydration, rows dormant. Re-pick adds the chosen file as a new Project and removes the broken one; sessions recorded against the old path fall back to their cwd's Project.
- **Folders in the file are read when a session is created or activated and when the app starts**; the file is not watched.
