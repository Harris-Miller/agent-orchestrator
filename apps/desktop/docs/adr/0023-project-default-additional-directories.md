# Project default Additional directories

A directory **Project** may carry default **Additional directories**, stored beside it in `projects.json` (`additionalDirectories` keyed by Project path; a Project with none has no key, so the file keeps its old shape). They are not a property of a session: the Project resolution seam (ADR 0022) hands them to every new session in the Project, and each **Tracked session** keeps the list it was created with, so editing the defaults never changes existing sessions or an already open draft.

- **Directory Projects only.** A **Workspace project**'s folders come from its file; it has no defaults and the key is ignored for it.
- **Override per session, never write back.** The Composer's cwd strip edits the Virtual session's own list ("Reset to Project defaults" re-resolves the Project). An ad-hoc VS Code "Add Folder to Workspace…" never writes to the Project either.
- **VS Code combination.** VS Code reads only the defaults of its Workspace cwd's Project (matched by path) and a new session gets the other Workspace folders first, then the defaults not already listed, minus the cwd, deduped. We considered letting the Workspace folders replace the defaults when the workspace has several folders; rejected, a user who set defaults on a Project expects them in every app, and the live folders still decide everything they list. The defaults are read at startup and again whenever a new Virtual session is ensured, so an edit on desktop reaches the next new session; a draft on the Workspace cwd that has not started takes the new set (a changed set re-Binds, ADR 0012).
- **Capability gate unchanged.** The list is only ever sent to an Agent that advertises `additionalDirectories`; otherwise the cwd strip hints that extra folders are ignored.
- **Removing a Project drops its defaults.**
