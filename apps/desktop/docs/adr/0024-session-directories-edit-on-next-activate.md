# A session's Additional directories are edited on its record and apply on next activation

ACP takes **Additional directories** only on `session/new`, `session/load`, `session/resume` and `session/fork`, so a live session cannot change them. A user can still change what a **Tracked session** will be opened with: the edit rewrites the session's record (Session History row), never the live session, which keeps what it started with and is not torn down. The next **Activate** sends the edited list. We considered fork-with-a-new-set (a new session per change) and a read-only view; rejected, a fork loses the conversation's identity and a read-only view leaves a wrong list uncorrectable.

- **Edited marker.** An edited record carries `directoriesEdited: true` (beside `additionalDirectories` and `workspaceFile`). An edited list wins over the Agent-side snapshot and over the re-read of its **Workspace file** on activation (ADR 0022), and an emptied list stays empty. An unedited session behaves as before. The Workspace file stays on the record: it still decides which **Workspace project** the session belongs to. A fork inherits the edited list and the marker. Lists from `session/list` never carry the marker.
- **What is editable.** Only the Additional directories. The Session cwd (the session's identity under ACP's cwd rule) and the Workspace file are shown read-only.
- **Where.** Every History row's `⋯` menu has "Directories…" on desktop and VS Code. Desktop adds through its directory picker; VS Code has no directory picker Host service, so it can only remove entries. A row shows a folder-tree badge when the session has a Workspace file and/or Additional directories.
- **No Workspace-file filter.** Desktop already groups sessions by Workspace project and VS Code filters by the Workspace cwd, so a separate filter was not built.
