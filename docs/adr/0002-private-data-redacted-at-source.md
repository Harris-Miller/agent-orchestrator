# Private data is redacted where it is logged, not scrubbed at export

**Private data** (see the desktop glossary) never reaches telemetry as plain text. A log argument that holds it is wrapped in Effect `Redacted` at the call site, so every Effect formatter, the OTLP logger included, prints `<redacted>`. An error `message` never interpolates it, and an error never keeps a cause that does, because both land on span exception events. The one exception is a message the user must read to act, which may name a file by its basename (an image the composer rejected). Identifiers (session id, launch target, pid, tool call id), counts, durations, exit codes, and ACP protocol discriminators are not private data and stay readable, so a person or an Agent reading traces can find the root cause of a bug (#193, #406).

**ACP objects reach telemetry only through allowlisted projections** (`libs/ui/src/host/acpTelemetry.ts`). Each projection copies what happened, when, and whether it finished (session update kind, tool call id, kind and status, stop reason, token counts, permission option kinds and outcome, elicitation mode and action, chunk and location counts) and never reads free text. Agent-supplied discriminators are free strings on the wire, so a value outside the ACP literal set is recorded as `unrecognized`, and an oversized id is dropped. ACP span attributes and log fields are a projection's branded output, never a payload field; the brand marks the output but cannot stop a raw field passed to `Effect.annotateCurrentSpan`, so review stays the guard. A canary test plants a marker in the free-text fields of each ACP object kind and asserts no projection emits it.

**Never recorded:** prompt, message, and thought text; tool call titles, `rawInput`, `rawOutput`, content, diffs and terminal output; location paths (only their count); plan entry text; session titles; elicitation messages, schemas and answers; permission option names and ids; the Agent's error `message` and `data`.

## Considered options

- **Scrub at the OTLP export boundary:** one place to enforce, but private data is free text inside messages and stack traces, so no rule can find it reliably.
- **`Redacted` in the ACP wire schemas:** RPC spans carry only `rpc.method`, so for prompts and updates it buys no telemetry privacy and forces `Redacted.value` through every Harness reader. Rejected for those, with one exception: the Agent's error response (`AcpError` `message` and `data`) decodes as `Redacted`. An error fails every Effect span on its way up (the RPC client span, the turn, the user action), and Effect renders the failure's `message` into each span's exception event, so no call-site wrapping can keep it out. The user still reads the text through `acpErrorMessage` / `acpErrorData`. An error of ours that must quote it for the user (a Handoff or spawn refusal) carries it in a `Redacted` `detail` field, never in its `message`.
- **Redact at the source (chosen):** cheap per call site and exact. The cost is discipline: a new log or error must follow the rule, and review is the guard, since tests do not assert on logs. For ACP objects the projections and their canary test carry that discipline.

## Consequences

- The dev console redacts too. There is one rule, with no Build target branching.
- The developer panel's RPC wire log is not telemetry: it shows the raw traffic in memory, credentials masked.
- Hub signals follow the same rule: allowlisted span, log and metric attributes only (tool name from the tool allowlist, else `unknown`; call outcome `ok` / `error` / `rejected`; duration; client kind, app session id, ACP session id, parent session id and launch target), never tool args, results, error text or tokens. The trace context the hub sends a Harness with a routed call is ids and a sampling flag, validated to hex. Harness logs carry session ids and the launch target as log annotations, never in the message text; a test plants a canary through a tool call and asserts it reaches no span or log.
- Known gaps, deferred: every `PlatformError` names the path it failed on, including those built by this repo's Tauri `FileSystemLive` (fixing that drops the path from all filesystem debugging); errors raised by the Tauri opener or VS Code can name the URL in their own message; npm's stderr copied into provider-runtime install errors can name cache or log paths. A schema decode failure of an Agent response is not a gap: Effect's `SchemaError` names the path and the expected type, never the value.
