# Widen Host services with OpenFile

Host services include OpenFile alongside BundledResource, ChildProcessSpawner, Clipboard, FileDialog, FileSystem, OpenUrl, OS, and Path so shared chat UI can open a referenced file in the Host editor without importing a host editor SDK. Surface for this change is `open(path)` (absolute path; the Host opens files and may reveal directories), `openImageData(image: Base64Image)` (an in-memory image with no file uri, limited to the `OpenableImageMimeType` literals and written by the Host to a temp file named with `openableImageExtension`, then opened), and a `supported` flag so callers render file links inert where the Host cannot open them. Every Host declares OpenFile explicitly: the Tauri Live Adapter reports `supported: false` and fails each call until the desktop file explorer lands (#169), rather than shared code reading OpenFile as an optional service. Live Adapters stay in host packages (`@lib/context-services-tauri`, `@lib/context-services-vscode-webview`); only host apps compose those Live Layers into the Host runtime. Chat link classification and dispatch are recorded in the ui ADR `0005-chat-links-via-host-services`. Image data travels over Host IPC as base64 because it already arrives as base64 in ACP content and data URLs; composing FileSystem plus `open` instead was not chosen because the webview FileSystem has no binary write.
