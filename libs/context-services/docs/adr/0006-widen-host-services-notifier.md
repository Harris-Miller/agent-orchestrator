# Widen Host services with Notifier

Host services include Notifier alongside AtomicFile, BundledResource, ChildProcessSpawner, Clipboard, FileDialog, FileSystem, OpenFile, OpenUrl, OS, and Path so shared UI can raise an OS Notification for an Attention event without importing a host notification SDK. Surface is `notify({ title, body, sound })` (fails with `NotifyFailed`), `isWindowFocused` (Host window focus, so the "only when unfocused" setting works where `document.hasFocus()` is unreliable, e.g. a VS Code webview), and `supported: 'os' | 'in-app'` so Settings can explain a Host that can only show an in-app message. The Notification sound is the system sound attached to the Notification (`sound`); there is no standalone sound method. Every Host declares Notifier explicitly: Tauri reports `supported: 'os'` via `tauri-plugin-notification`; VS Code reports `'os'` or `'in-app'` depending on whether the webview `Notification` yields an OS toast. Callers swallow `NotifyFailed` so a Notification never fails a turn. Live Adapters stay in host packages (`@lib/context-services-tauri`, `@lib/context-services-vscode-webview`). The ui-side sound decision is recorded in ui ADR `0006-notification-sound-rides-notification`.
