# Theme-split curated file-icon packs in `libs/ui`

Composer and transcript Markdown Link chips need file-type glyphs that look right on both desktop and the VS Code webview. We vendor small curated SVG packs under `libs/ui/assets/file-icons/` (`original` from vscode-icons; Catppuccin latte / mocha) and resolve by the painted palette id (`default-dark` → original pack, every other dark palette → mocha, every light palette including `default-light` → latte). Sources stay as SVGs for license clarity; runtime uses TypeScript string modules → data URLs so the webview IIFE build (`assetFileNames: 'main[extname]'`) never emits colliding SVG assets.

Rejected: VS Code `workbench.iconTheme` IPC (host coupling, explorer parity deferred), a single shared pack (wrong look on Catppuccin themes), and the `vscode-icons-js` npm helper suggested in #111 (extra dependency for a ~25-key hand map). Trade-off: explicit asset footprint and a hand-maintained basename/extension map instead of full explorer theme parity.
